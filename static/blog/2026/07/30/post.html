hello! i've been spending the last few days working on implementing commenting to my site. i finished with this today, and my implementation has been pushed to the site! you should now be able to add comments to pages on my site. the whole implementation was made in a few short CGI bash scripts. you can find them at this site's git repo. i am very new to shell scripting, so they are... quite messy. i will probably forget what any of this code does within a few weeks, but i'm pretty sure that most of the current code will be here to stay for a while. onto the technical details of how this works, the current implementation allows for commenting on any html page on the site. in the base html file, i added a commenting wing to the right of the main content window which has an HTML form for submitting comments, and a section below it which displays the comments. the form submits comment data through the builtin form target parameter, so i didn't need to use any javascript for anything. in the site's build script, i appended a ?page query parameter equal to each built html file's location to the target so the posting script knew which page the comment was being posted on. once the content is submitted to the comment.cgi, it just reads the name and comment parameters from stdin and writes them my server's filesystem. the very basic anti-spam measure that i wanted to implement was only allowing one comment per IP address. i wanted it to be easy to display the comments in descending time order while still doing this, so i decided on a somewhat elaborate file layout for each page. in each page's comment directory, each individual comment is stored in its own folder with its timestamp as its name. once all of the comment details are written to files in the folder, by-ip/$ip is symlinked to the comment's directory. this lets me check if a poster's IP is already in the by-ip directory - and if so, replace their old comment with the new one. posting out of the way, displaying the written comments is implemented pretty trivially. the get-comments.cgi script iterates over all of the comments of a page in reverse order, and prints out their details in an html document. it also of course sanitizes the written content to prevent anybody from running arbitrary javascript code or embedding anything on my site. the cgi script is embedded into the base html through SSI so the comment listing is generated dynamically on each page load. i think i probably did an ok job with security. i have tried a lot of stuff, and i was not able to figure out anything i could put in the input fields to execute arbitrary shell commands on my server or get around my html escaping function. i would be pretty surprised if i managed to get my site or server compromised from this implementation. if you discover that this can happen anyways please contact please. thanks the main thing i am expecting to have to worry about is spam. with the "anti-spam measure" mentioned earlier, the most the average person could do is put a few mean words on every page they can find. i've been too lazy to look over my access log, so i have no idea if this site ever actually gets traffic from outside of close circles. if it does, i'm expecting this to happen within maybe a few days. this will motivate me to implement a proper deletion/ip ban system, and maybe even a simple filter. that's all for today. thanks for reading ~nix
